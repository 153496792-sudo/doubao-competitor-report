# 范本格式规范（面向面试官的专业竞品报告）

## 读者与基调

- 读者是专业的面试官/评审，不是大众读者。全文以提高"干货比"为导向：去芜存菁，只保留有信息量的内容。
- 产品经理视角，不做商业分析师式的泛化分析；除非确实重要，不写商业环境、环境成熟度等章节。
- **观点的可靠性永远是第一位**：每个观点必须有可靠证据（数据来源、案例、人际渠道、亲身体验），切忌被面试官问倒。
- **不编造证据**：人际渠道信息、访谈、证言、亲身体验若未实际获得，不得虚构；缺失时明确标注"待补充/基于公开资料"。

## 标题与编号

- 所有层级标题使用数字编号：一级"1."、二级"1.1"、三级"1.1.1"（如 1.6.1），四级标题同样编号；不使用"一、二、三"式文字编号。
- 文档左侧生成目录，便于面试官快速浏览与定位。
- **正文开头不得重复文档标题**：文档标题由飞书标题栏展示，正文首行不要再次加粗居中显示报告名称，避免重复；直接以副标题（整理时间/版本）或导语开始。

## 行文

- 不写大段长文：适当分段，让重要观点不被淹没，减轻阅读负担。
- 每个段落/条目集中表达一个观点，观点先行、证据随后；条理清晰，便于面试官抓重点。

## 竞争态势写法

- 每个玩家固定结构：**产品介绍（定位、规模等）→ 优势 → 劣势**；优劣势详细铺开阐述，不能一句话带过。
- 总览表格可选：置于详细阐述之后，承载观点简述，加强整体印象（表格本身阅读不便，不放详细内容）。
- 优劣势必须写明对**用户价值、商业价值**的有利/不利影响，并突出与其他竞品的**差异化**。
- 简要表述要适当归纳：如"无 XX 功能"应提炼为"针对 XX 客户/XX 场景的功能存在不足，可能导致 XX 问题"。

## 定位演变历史

- 两列表格：**事件列**（突出与定位相关的新版本、新功能，不放大事件记录如融资）+ **定位列**（对新版本/新功能涉及的"产品定位"变化进行解读）。
- 表格之后按阶段做总结，凸显宏观总结能力。

## 核心竞争策略 / 优势

- 只写稀缺、独特、或竞品做得更好的点；所有玩家都有的基本功能不写。
- 强调"差异化"（人无我有、人有我优）：每点配与其他竞品的对比和证明（论据 + 论证过程），经得起面试官质疑。
- 某点其他竞品也做得很棒时，可将其作为"第一阵营"与其他竞品比较。

## 证据原则（关键）

- **数据与事实**：标注可靠来源（IDC、Gartner、中国信通院等第三方机构；招股书/财报；官网信息需注明并自行核实）；来源不明的写"据公开资料估计"或省略。
- **案例与体验**：优先人际渠道（行业人士、实际用户的证言/案例）与亲身体验；仅凭官网宣传不足以支撑观点，需额外验证可信度。
- **观点与证据一一对应**：每个策略/优势/能力都要回答三问——给用户带来了什么业务价值？给竞品带来了什么商业价值？用什么客观证据证明（而非竞品自己的宣传）？

## 场景小节结构

每个核心场景按"痛点 → 方案 → 优劣势 → 案例 → 建议"展开：

1. 业务痛点（从具体复杂场景出发，写清重难点）
2. 解决方案（本竞品如何满足该场景、解决重难点）
3. 优劣势（与至少一个竞品对比，写清差异）
4. 客户案例（企业名称 + 背景 + 痛点 + 使用效果，尽量含数据）
5. 建议（对功能/运营的改进建议）

关键页面配截图并解读；核心逻辑要系统化讲解（如"满足条件的订单才会自动审核——有哪些条件？分别对应哪些业务场景？"）。

## 总结

机会导向：值得借鉴的经验、需避免的错误、对竞品的明确建议、作为竞争对手的打法、与自身经验结合的运用。

## 付费意愿分层口径

- 小微企业：付费意愿弱、价格敏感，倾向免费/低成本工具。
- 中型企业：付费意愿较强，关注销售效率与 ROI，是 SaaS 订阅主力客群。
- 大型/集团企业：付费意愿最强、ARPU 最高，但要求私有化/信创适配、深度定制、本地化服务网络。

## 配图规范

- 仅使用公开渠道可获取的图片（官网截图、官方演示、公开评测图），每张图标注图源。
- 关键页面截图优先用于"场景与体验"部分并逐图解读；找不到合适配图时用文字描述替代，不得编造或伪造截图。
