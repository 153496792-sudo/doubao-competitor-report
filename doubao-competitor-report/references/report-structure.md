# 报告结构规范

文档标题：【产品名】竞品分析报告。全文标题使用数字编号（一级"1."、二级"1.1"、三级"1.1.1"），并生成目录，便于快速浏览。

**正文开头不得重复文档标题**：文档标题已由飞书标题栏展示，正文第一行不要再加粗居中重复报告名称；直接以副标题（整理时间/版本说明）、导语或第一章内容开头。

**读者画像：专业的面试官/评审，不是大众读者。** 全文以提高"干货比"为导向：去掉可有可无的内容，观点有可靠证据支撑，不写宣传腔。观点的可靠性永远是第一位——每一个观点都要有论据和论证过程，切忌被面试官问倒。

## 一、行业分析（约占全文 20%）

定位：背景交代——讲竞品所处的行业，不是直接开始讲拆解的竞品。除非非常重要，去掉商业环境、环境成熟度等泛化章节（产品经理不是商业分析师）。

1. **行业背景与市场规模**
   - 先给结论：市场规模到底有多大（量化数字），让面试官快速了解观点；数据注明可靠来源。
   - 没有直接数据时，可基于客户行业规模数据推导，并注明口径。
   - 引用 1-2 个权威数据点（规模/增速/渗透率）+ 一句趋势判断；数据必须来自可靠来源（IDC、Gartner、中国信通院、招股书/财报等）。
2. **客户群体**：按规模/类型分层概述客户画像，一句话点明各层核心诉求。
3. **客户痛点**：每条痛点先给【简要概括作为小标题】（如"销售过程黑盒""商机漏斗不可见"），再配一两句具体业务场景描述。精简版 2-4 条、完整版 4-6 条。
4. **SaaS 解决方案**：方案必须与痛点一一对应，每条以"针对 XX 的痛点，YY 产品的解决方案是……"开头，体现结构化思维，方便面试官快速理解。
5. **付费意愿**：按企业规模分层，各一两句说明强弱及原因；篇幅允许时可并入客户群体，避免行业分析膨胀。
6. **竞争态势**
   - 每个主要玩家按固定结构展开：**产品介绍（定位、规模等）→ 优势 → 劣势**，优劣势要详细阐述，不能一句话带过。
   - 内容多时可先做总览表格（观点简述），放在详细阐述之后，用于加强整体印象。
   - 优劣势必须【明确说明】对用户价值、商业价值产生的有利/不利影响，并突出与其他竞品的【差异化】。
   - 简要表述要适当归纳：如"无多人盘点功能"应提炼为"针对 XX 客户/XX 场景的功能存在不足（没有 XX 功能），可能导致 XX 问题"。

## 二、定位

1. **目标客群**：细分核心客群及其业务诉求。
2. **核心产品/服务**：对产品主要模块【逐个】进行简要描述（如 ERP 的采购管理、订单管理、库存管理等），体现对产品全面、正确的认知；每模块精简版 2-3 个要点、完整版 3-5 个要点。
3. **定位演变历史**
   - 用两列表格：**事件列 + 定位列**。事件列突出与"定位"相关的内容（发布新版本、新功能），不是大事件记录（融资等可调整或去掉）；定位列对新版本、新功能涉及的"产品定位"变化进行解读。
   - 表格之后按阶段做总结，凸显宏观总结能力。
4. **核心竞争策略**
   - 只选择稀缺的、独特的、或竞品做得更好的点；所有玩家都有的基本功能不写。
   - 强调"差异化"（人无我有、人有我优）：每点增加与其他竞品的对比；某点其他竞品也做得很棒时，可将其作为"第一阵营"与其他竞品比较。
   - 每条必须有可靠证据支撑（具体产品功能、公开数据、客户案例、人际渠道信息或亲身体验），并说明：给用户带来了什么业务价值？给竞品带来了什么商业价值？
5. **优势 / 挑战**
   - 优势是"相对的"（人无我有、人有我优）：每点配与其他竞品的对比和证明（论据 + 论证过程）；所有竞品都做得同样好的点不写。
   - 写完挑战后顺势写对竞品的建议（切实可行，容易加分）。
6. **不足与建议**
   - 建议要写完善：思考"为什么该产品不采取此策略？是不知道，还是权衡了利弊？"，并把利弊写进报告。
   - 寻找同行业或其他行业通过该策略获得较大回报的玩家，分析其成功原因，判断目标竞品能否借鉴及为什么（如细分解决方案的难点：门槛较高？难以规模化？）。

## 三、能力与资源

- 突出**稀缺性**：该产品【独特】的能力/资源，或虽竞品也有但该产品【更优】；其他竞品也做得好的可一并提出，证明视野开阔。
- 说明能力/资源带来的【独特价值】，并用案例证明。
- 证据方式二选一或并用：1）与其他竞品对比，体现独特优势；2）人际渠道（行业人士、实际用户的证言或案例）或亲身体验。
- 官网等宣传内容除非有独立论证与论据，否则不作为可信证据（需额外验证可信度）。

## 四、场景与体验

- **核心功能场景**：精简版 2 个、完整版 2-4 个最有代表性的场景，按"痛点 → 方案 → 优劣势 → 案例 → 建议"的逻辑展开：
  1. 业务痛点：从具体、复杂的业务场景出发，写清重难点；
  2. 解决方案：本竞品如何满足该场景、解决这些重难点；
  3. 优劣势：与至少一个竞品对比，写清差异；
  4. 客户案例：以某企业为例（背景 + 痛点 + 使用效果，尽量含数据）；
  5. 建议：对功能/运营的改进建议。
- **关键页面截图并解读**（面试重点，特别是跨行求职）；对核心逻辑做系统讲解（如"满足条件的订单才会自动审核——有哪些条件？分别对应哪些业务场景？"），证明对产品逻辑与业务场景有全面理解。
- 尽量补充人际渠道信息或亲身感悟（用户访谈、行业人士观点）；缺少一手信息时明确标注"基于公开资料"，不虚构。
- **用户体验**：亮点与不足各 2 条，注明来源。

## 五、总结（机会导向）

- 总结竞品需要重点改进/发展的方面；通过分析得到哪些值得借鉴的经验、哪些需要避免的错误——竞品分析的目的就是找到可以"利用"的地方。
- 具体说明：1）竞品未来应如何发挥优势、弥补劣势（明确建议）；2）作为竞争对手，面对其优劣势应如何展开竞争（看到的机会）。
- 结合自身/过往经验谈运用（如差异化定位、我们可建立优势的空白点），这是高频面试题。
